## 速答

本次工作沿着「后端能力验收难跑通、不符合用户直觉」这条路打通了核心阻塞，并把设置页前后端错误契约对齐。结论：

1. **致命阻塞已修**：GitHub 更新源 sha256 来源 bug（`build_update_asset` 只读标准 release API 的 `asset.digest`，而该字段默认不返回）——改为额外拉取 expanded_assets 端点解析 digest。修复后 QmClient/TaterClient/BestClient 等 GitHub 客户端不再一律降级为手动下载。
2. **错误契约结构化**：更新链路 7 个 command 从 `Result<_, String>` 升级为 `Result<_, IpcError{code,message}>`，前端按稳定 code 映射文案，不再靠字符串 `includes` 猜后端意图。
3. **识别核心有了回归护栏**：`normalize_client_id`/`infer_client_identity`/catalog 匹配从"无单测"补到有直接覆盖。
4. **client_id 收敛**：前端 Steam 判断从 `install_dir.includes("steamapps")` 路径启发式改为 `install_source === "steam"` 结构化字段。
5. 全量门禁 `FAIL=0`；后端测试 163→167，前端测试 38（含新增 IpcError 映射）。

仍需用户在能访问 GitHub 的环境手动补验：真实 release 下载、真实 sha256 校验、桌面端到端联调（自动化只覆盖到本地 fixture + 纯解析逻辑）。

## 背景

用户判断「后端能力验收很难跑通，很多地方不符合用户直觉」，并确认两个方向：主界面沉浸式 UI 保持（仅占位符待填），真正驱动后端的设置页面前后端不匹配才是核心；优先打通验收链路。

经逐行核对，定位到两类交织问题：
- **验收跑不通**：GitHub sha256 来源实现与规格不符（A1，致命）、smoke 只跑 loopback（A6）、识别/更新核心无单测（A7）。
- **设置页前后端不匹配**：错误靠字符串匹配（C1）、Steam 判断靠路径启发式（C3）。

注：调研报告（2026-06-07）记录的「安装事件未监听/历史无 UI」（A4/A5）在阶段 0 收口的 +907 行工作区改动里**已经解决**（UpdatePanel 已监听全部 6 个 download/install 事件 + 接入恢复/历史数据层 + C2 空版本展示）。

### 阶段 1：错误结构化（C1）

提交 `e7083e6 feat(ipc)`。

- `models.rs` 新增 `IpcError{code,message}` + `classify_error_code` + 8 个 `IPC_ERROR_*` 常量。`From<String> for IpcError` 走 classify，使底层 String 错误自动分类。

设计折中：`classify_error_code` 内部仍是模式匹配，但已从前端散落的 `includes` 收敛到后端集中、可单测的单一函数。彻底结构化（底层 `thiserror` 枚举）是后续工作。

### 阶段 2a：修复 GitHub sha256 来源（A1，致命）

提交 `5eca5c2 fix(update)`。

根因：`build_update_asset` 只读标准 release API 的 `asset.digest`，但 GitHub `/releases/latest` 的 asset 对象**默认不返回 digest**——digest 只在 expanded_assets 端点的 HTML 里。导致几乎所有 GitHub 客户端降级 `Manual`。

修复（TDD）：
- 新增 `parse_expanded_assets_digests(html)`：按 `clipboard-copy` 元素的 `aria-label="Copy to clipboard digest for {name}"` + `value="sha256:{digest}"` 属性对解析，不引入 HTML/regex 依赖。锚点来自 curl 实测真实响应。
- 新增 `fetch_expanded_assets_digests(owner,repo,tag,route)`：拉取 expanded_assets HTML 并解析。**失败时 `unwrap_or_default()` 回退空映射**，不阻塞更新检查主流程。
- `build_update_asset` digest 优先级：**expanded_assets > asset.digest > Manual**。
- 安全边界不动：`local_smoke.rs` 的本地地址 gate 未放宽，expanded_assets 的 HTTP 请求走标准 reqwest（受 `network_route` 代理/镜像支持）。

### 阶段 2b：补识别核心单测（A7）

提交 `4695d1e test(client)`。

codegraph 标注的 no covering tests 核心符号补直接覆盖：

### 阶段 2c：expanded_assets 端到端集成测试

### 阶段 3：client_id 收敛（C3）+ C2 现状

## 补充：下载面板 UX 重构（edb53c3）

用户实际跑应用后反馈三点，逐一修复：

1. **网络路由输入 bug（最痛）**：`onChange` 每键触发 `updateAndSave`（异步落库）→ `props.settings` 回流 → 重渲染时输入框 value 被中间状态覆盖、失焦/"tab 出去"。改为 `routeUrlDraft` 本地草稿：`onChange` 只更新草稿，`onBlur` 才落库。`useEffect` 在外部变化（模式切换/设置加载/保存回写）时同步草稿。
2. **布局拥挤 + 恢复/历史莫名其妙**：「客户端|可用更新」和「恢复任务|安装历史」两组并列 `grid` 合并为**单列连贯流**（选客户端→检查更新→下载→安装）；恢复/历史改为**折叠的「历史记录」**（仅有内容时显示），用用户语言，隐藏 `cache_state`/回滚目录/`package_kind` 等内部概念。
3. **下载与客户端整合**：多客户端时客户端区显示**下拉切换**目标客户端（`setDefaultClient` + 刷新 artifacts），单客户端显示名称。客户端信息与下载流程整合到一个连贯面板，不再割裂。
